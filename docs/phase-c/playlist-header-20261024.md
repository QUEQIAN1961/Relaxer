# 歌单创建、歌单页头及展开播放按钮修复

本轮基于正式发布后的 main `44eaee9da725112cbe7a46fcb797fd975f9ef83f`，作为 0.2.1 的独立增量测试构建交付。已发布标签和发行包继续保留。

## 创建歌单

`ConfirmDialog` 使用 `DialogButtonBox` 作为 footer。Qt Quick 的 `Dialog` 会自动连接 footer 的 accepted/rejected 信号；组件又手动连接了一遍，造成一次确认发出两次 accepted，继而创建两条数据库记录。修复删除额外连接，保留 Qt 原生确认路径。此修复同时覆盖侧栏、歌单页、批量新建并加入及歌曲右键菜单的新建入口。

回归使用实际按钮点击检查数据库中只增加一份歌单，并检查 accepted 信号次数。旧的重复连接已用相同用例复现“期望 1 条、实际 2 条”。取消、改名、主动分别创建两个同名歌单也分别验证，避免通过按名称去重掩盖事件错误。名称输入框支持回车确认。既有歌单记录由用户管理，本轮不执行数据去重迁移。

## 歌单页头

此前 `Artwork` 虽指定 width/height，却作为 Layout 子项使用，布局最终采用组件的 62×62 隐式尺寸。新的独立 `PlaylistHeader` 显式管理封面及四行内容，按用户提供的展开/收起参考图组织：

1. 第一行：播放全部、随机播放。
2. 第二行：歌单选项、上移、下移。
3. 第三行：歌曲数量、播放次数、标签。
4. 第四行：简介，展开时最多两行，收起时单行省略并靠右。

展开封面为 160×160 逻辑像素。下滚时封面收为 78×78，与两行 36 高按钮及 6 像素行距等高；两行信息同时向右移动。一个 220 ms OutCubic 进度统一驱动尺寸和坐标，反向输入从当前进度继续。减少动态效果设置启用时立即切换。滚轮可在封面/页头或歌曲列表触发；第一步切换页头，后续步骤交给歌曲列表滚动，与参考 Widgets 行为一致。空歌单和短列表也能折叠，布局回流不会自行反复展开。

歌单选项继续提供信息编辑、改名、封面及缺失歌词查找；调整歌曲顺序沿用现有桥接接口和筛选/排序限制。歌单歌曲表采用播放次数列，本地音乐保留原列。

## 展开播放

移除展开播放页右上角的额外窗口全屏按钮。收起按钮、底栏展开/收起播放入口和原有窗口行为继续可用。原测试中依赖已删除按钮的断言改为检查按钮不存在，并通过原窗口方法及 Escape 验证全屏还原。

## 验证与交付

`relaxer_playlist_header_tests` 纳入 QML 回归配置，覆盖四种创建确认、两个新建并加入入口、取消/改名/同名创建、宽窄窗口、空/六首/长列表、长信息、动效反向、减少动态效果、歌曲排序和展开播放按钮。实际测试日志、截图、源码身份和独立解压启动结果随本轮交付报告保存。本轮专项验证不替代历史全量回归或独立 Harness 验收。
