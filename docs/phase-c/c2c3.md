# C2+C3 · library, playback and queue boundaries

Baseline: Harness R13 accepted C1 Fix1 `a4fbda6d5919e5d53771db394d5f94f16f0810b5`.
Development version: V0.2.1-dev-c2c3. Current batch awaits independent Harness.

## Ownership and commands

The optional RelaxerQmlUi module and its private ABI/pin policy are preserved.
The host still chooses one UI, owns the original dataRoot lock and loads QML
before any data creation. The QML session owns one existing Library and one
existing PlaybackFacade/Playback/Queue. No QML MediaPlayer or new connection is
introduced. Playback/Queue/MIDI/AI/translation/session algorithms are unchanged.

QmlShell owns the existing facade, app/playback bridges, library source/proxy,
playlist model, library command bridge and queue projection. QQmlEngine/root
objects are destroyed first, then models/bridges, then facade; Library outlives
the shell. C++ context objects have explicit CppOwnership. Delegate identities
are values; they never retain a C++ row pointer or stale model index.

LibraryBridge invokes existing Library commands for favorites, playlist CRUD,
membership and original-order movement. Reference removal follows the Widgets
context menu: facade.forget, then Library.remove, retaining files. QML confirms
destructive reference/playlist deletion. Full import management and advanced
lyrics/settings/AI remain Widgets features for later phases.

PlaybackBridge delegates play/pause/next/previous/seek/volume/mode and queue
selection/removal to the existing facade. Queue selection uses the same play
command with existing IDs; no new queue algorithm is introduced. The queue view
shows original submitted order, rather than pretending it is a shuffle forecast.
Append/reorder without restarting a current session is not exposed by the
existing facade and is not invented here. Existing forget/removal is supported.

Mute is actual core volume zero. Last nonzero mute volume is a UI preference in
the existing settings table (`qml.lastAudibleVolume`), so recreating a window
does not reset the actual volume. No schema/migration or second player state is
added. Seek dragging retains a tentative value only during the gesture, commits
through facade on release, and validates the original track key. Keyboard seeks
also go through the facade. The engine remains the progress authority.

## Models and large libraries

Library::trackCount adds only a read-only COUNT query to the existing owning
connection. It returns a scalar instead of materializing all Tracks. It is not
claimed that SQLite COUNT has constant physical I/O under every database size.

TrackListModel is one read-only snapshot of the current local/favorites/playlist
scope. Library's coarse changed signal is coalesced; no new database connection
or persistence is inside a model. Roles include qint64 trackId, title, artist,
album, duration and favorite. Decimal trackKey/playlistKey additionally preserve
exact command IDs across JavaScript's number precision boundary.

TrackFilterModel filters/sorts that snapshot with QSortFilterProxyModel, preserves
selection by ID across filtering/sorting, returns selectedRow=-1 for a hidden
selection, and clears deleted IDs. Per-range proxy changes coalesce their
additional count/selection notifications. Filtering reads source strings directly
instead of repeatedly boxing them into QVariant. A full content change still
costs O(N) snapshot read/map and a reset; this controlled adapter cost is measured
at 0/1k/10k. No claim of incremental database notifications is made.

Playlist model exposes only name/member count and responds to Library::changed,
not progress/statistics updates. QueueListModel reads the facade's authoritative
IDs and builds display metadata on content/queue changes; shared ID storage lets
progress events avoid row scans and resets. Missing ID detection is a read-only
notification: the command bridge rechecks it and calls facade.forget after the
model reset. No independent writable Queue, shuffle history or persistence exists.

ListView reuses and caches only visible delegates. Native probe metrics include
first frame, synchronous filter/sort cost, next-frame response for page switches
and requested scroll steps, delegate bounds and Windows memory. They are not a
claim about physical display FPS or human-perceived smoothness. Fixtures are
prepared in a separate process under a new synthetic dataRoot; no user data is
read or included in delivery. Memory is sampled before the legacy materialization
benchmark; retained QString/vector capacity is a lower-bound payload estimate,
not an allocator traffic counter.

## Verification and scope

Original tests remain, with only development-version/title expectations updated.
New model behavior, real gestures, modes, missing files, restore and actual
Widgets/QML command parity are tested. A Windows locked-file test fixture was
corrected to remove media after closing its previous decoder; no core assertion
or real file deletion behavior was weakened. All failed build/test logs remain.

Final batch validation uses one clean Release build/full CTest, four services,
native portable dual entry/missing-Quick checks, fresh staging packaging and
Git/bundle/ZIP/member hashes. The existing source fingerprint policy is retained.
C1-P301 is developer-fixed with functional/measured evidence, pending independent
review; other 23 inherited P3 issues remain. R12's three engineering findings
were already independently closed by R13. No C4/C5/C6 or formal release begins.
