# C1 冻结与 C2 输入

开发方结论：可将本轮冻结为 V0.2.1-dev-c1 / C0+C1 开发交付。它具备进入 C2 设计/验收准备的代码和资料基础；独立 C1 Harness 尚待用户下一轮安排。本轮停止扩展，不创建正式 v0.2.1 标签，也不执行 C2。

已具备：正式基线恢复与身份、完整迁移蓝图、可选实际 QML 主窗口、四页导航、主题/组件、真实 C++ 状态桥、唯一 Playback/Library、默认完整 Widgets 回退、旧完整回归和 C1 自动化、原生部署/关闭、基础性能方法、源码/历史/哈希交付。完整性门禁还要求最终 ZIP 解压启动与 bundle 恢复的交付验证结果随总包提供。

## 下一轮建议

1. 独立 Harness 先检查本轮 UI 互斥、生命周期、数据选择、真实状态、三 DLL 与部署闭包、完整旧测试和数据保留。
2. C2 新建 typed LibraryModel / playlist read model；优先消除 C1-P301，用既有 Library 增加最小只读计数/分页接口或合适的值快照策略，所有 SQLite 访问仍在拥有线程。
3. 定义 title/artist/album/duration/favorite 等明确 roles，保持稳定 trackId，决定排序/筛选/selection 的模型协议；不复制业务 Queue，不从 QML 直接查询 SQLite。
4. 用相同 0/1k/10k/更大库规模测首批行、过滤/排序/刷新、内存与页切换，先证明模型不会阻塞 GUI，再扩展控件。
5. 播放详情、seek/volume/队列完整迁移留待 C3；歌词留待 C4；AI/付费同意/未保存预览/设置外观留待 C5；最终默认切换留待 C6。

C2 不应以完整 Qt Widgets 已存在为由让两个 UI 同时创建 Library/Playback；也不能为了性能另建用户数据目录或绕过 AI 协调器。继承的23项开放P3台账需保持可追踪；正式V0.2.0交付、tag与提交继续保护。
