# Phase B5.1 Behavior Contract

## Audited B5 behavior

- `LyricsLookup` owns lyric search, translation controls, preview, and saving.
- `BrowserTranslation` implements Bing/Baidu browser translation through CDP. The lookup UI persists the provider and can start automatic translation after accepting remote lyrics.
- Translation runs as multiple web requests, first in line groups and then one line at a time when alignment fails. Successful results are attached and saved without a user preview confirmation.
- `sourceLyricsForTranslation` filters existing paired translations; `attachTranslations` preserves the local timed-line format. `Library::saveLyrics` is the existing persistence path.
- The existing `Library` settings table and `SettingsStore` facade are the only settings store. The SQLite schema and Lyrics parser remain unchanged.
- Translation tasks already have per-track tokens, a generation counter, cancellation, reply abortion, and close confirmation. These protections must be retained and strengthened for the AI request lifecycle.
- Phase031 tests cover CDP/browser contracts, existing bilingual display, preview alignment, translation progress, timeout/failure preservation, settings persistence, and close/cancel behavior. Only assertions that require the retired browser translation product behavior may move; unrelated service and compatibility coverage remains.

## Frozen B5.1 behavior

1. Searching, accepting, importing, or switching songs never starts a paid AI request automatically. A user action starts one whole-song request for one selected track.
2. The request sends only source lyric text and track context to the explicitly selected DeepSeek provider. It uses the current confirmed model and thinking settings; it never infers a provider from a key, changes models, raises effort, chunks a song, or retries automatically.
3. Provider configuration, API keys, model metadata, global defaults, and lyric-translation overrides live in the AI service layer and existing Library settings. Credentials use the Windows Credential Manager. No new database or schema is introduced.
4. Translation input receives stable local line IDs. The service accepts only a complete JSON response with exactly one non-empty, single-line translation per expected ID. All timestamps, source text, line order, and save decisions remain local.
5. A valid result is previewed before saving. A failed, cancelled, stale, truncated, or invalid response never changes the saved lyric document. Existing bilingual lyrics are detected and never silently overwritten.
6. Cancellation stops local processing; it does not claim to revoke a request already received by DeepSeek. Tests use a local mock only. Real API quality and billing remain user acceptance work.
7. Browser translation controls and its user setting disappear. The old implementation may remain only when needed to protect unrelated compatibility tests or module boundaries; it is unreachable from normal user workflows.
8. Product version `1.10.0`, changelog, database schema, lyric parser, playback, Queue, B3 matching, B4 appearance settings, historical branches/tags, and prior Runtime/user data remain unchanged.
