# B5.1 XHigh-R2 quality checkpoint

Parent checkpoint: 5c712abbadb5632497367fac44da9833de0722cd (XHigh-R1).

This bounded follow-up addresses defects demonstrated by red tests and parser/source review:

- Normalize API keys once through the shared printable-ASCII policy. Trim outer ASCII spaces, reject embedded whitespace/control/non-ASCII characters, clear the editor and controlled temporary copies. Windows credential storage uses the same policy. This is best-effort copy reduction, not a guarantee that all implicitly shared Qt/network/OS buffers are zeroized.
- Make model-catalog persistence transactional at the runtime boundary: failed SQLite writes restore the previous live registry and keep the previous configuration. Publish one runtime completion signal including persistence failures, so the page cannot report a failed save as a successful refresh.
- Make population guards nest-safe, remove duplicate refresh paths and debounce style writes for 250 ms. Preserve a pending style draft across unrelated settings changes and flush it on page exit/destruction. Require stored credentials for model actions, show full model-name tooltips with explicit popup elision, and preserve/display unsupported target-language settings without sending a request.
- Clear unsaved-preview state after a successful save and render the stored lyrics normally. Add the existing bilingual metadata marker to both plain and timed new output. Refuse unsupported translation languages at the feature boundary; historical unmarked bilingual files retain the existing heuristic.
- Reject model-generated timestamps anywhere, all supported line separators, and LRC control metadata. The unchanged player parser matches timestamps and offset tags anywhere: the Harness description that embedded timestamps cannot create timeline entries was incorrect. An injected offset can also alter global timing. Source preparation now follows the parser's existing inline-offset row exclusion.
- Guard the nested consent event loop against repeated activation and recheck song selection, track fields, source digest, configuration and credential validity before dispatch. A source/configuration change while consent is open now produces zero POSTs.
- Validate JSON token/capacity integers before floating-point conversion to qint64. Invalid or partial usage is displayed as unavailable rather than a fabricated count.

Compatibility boundaries: version 1.10.0, database schema, original Lyrics parser, Queue/playback, B3 matching, B4 appearance and global DPI behavior are unchanged. New merged lyric output intentionally remains UTF-8/LF; tests prove text/timing compatibility for UTF-8, BOM, CRLF and UTF-16 LE/BE inputs, not byte-for-byte encoding preservation. Unknown JSON extension fields remain for the original forward-compatibility requirement (D-16).

Validation: a new Release directory completed all 194 Ninja steps and unfiltered CTest 39/39 (157.32 s). QtTest totals: 634 passed / 0 failed / 4 historical skips; AI infrastructure 17, AI translation 30, AI widgets 12, Phase031 33 (including QtTest init/cleanup and data rows). All provider requests used local mocks and fake credential stores. Red-test logs, full raw reports, independent runtime evidence, source identity and final commit/archive receipts are delivered separately. No real DeepSeek request, personal credential access or paid call was performed.

Historical DPI work, real sound-device playback, real API/translation quality and user acceptance are outside this checkpoint. This is a handoff for the third independent Harness run, not formal B5.1 closure.
