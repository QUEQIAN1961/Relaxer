## 候选入口与数据隔离

当前候选入口是 `RelaxerQml.cmd`，或 `runtime/Relaxer.exe --ui=qml --data <独立测试目录>`。不要把本次局部验证当作原有启动器完整 readiness 验收。候选不写入 `relaxer-ready.json`，不伪造全量通过证明；`RelaxerStart.exe` 保留作后续启动器验收输入，本轮请用上述 QML 入口。

测试数据请使用独立目录或已有资料副本。不要覆盖用户原始资料或历史候选。源码包和 Git bundle 单独提供，不包含本机真实资料、凭据或构建缓存。

## 建议验收顺序

1. 准备多首有 ⚠ 候选的歌曲：首次进入自动推荐；连续点击使用无需逐首确认；完成后跳转下一个待处理项、末尾循环、无待处理时停止；更改候选后仍使用实际选择。
2. 核对“无歌词 / 无翻译 / 多选 → 取消 / 全选”：全选仅含当前筛选；取消退出并清空；操作不改变当前播放和队列。
3. 核对纯音乐按钮位置与 35:65 比例，确认后进入下一项；核对三栏上下边界、1000×660 与常用窗口大小，以及高 DPI。
4. 滚动原文/双语歌词：定位行高亮和横线、时间定位播放、回到当前歌词、空闲恢复；确保播放不会因普通拖动自动跳转。
5. 重复点击当前本地、歌单、个人、设置、喜欢及具体歌单，检查无重复切换动画；在展开播放页和切换进行中检查实际导航目标。
6. 外观五种模式的标题栏、保存/覆盖/默认、未保存三按钮，以及 p12–p14 的色块/图片/模糊布局；检查接受/取消、保存重开和旧主题兼容。屏幕取色、高 DPI 与多显示器由 Harness 原生交互验证。
7. 用方向明确的宽图、竖图测试页面与底栏接缝；分别覆盖左右共图/分图、共用开关、缩放窗口、模糊强度和导入面板。共享的是图片坐标，区域模糊仍按原设定处理。
8. 检查真实歌词搜索、多个候选排名更新、离线缓存与大列表。存在翻译预览/运行任务时需确认冲突；取消保留预览，保存失败不得跳歌或丢预览，成功后才丢弃冲突任务。

## 开发方定向验证

只构建 `Relaxer`、`RelaxerStart`、`relaxer_manual_ux13_tests`；只运行本次专用定向用例和一次部署后原生启动冒烟。首次测试环境缺失 QtQuick 导入路径及后续断言修正的记录均保留，不覆盖失败历史。开发中日志的 HEAD 指向基线、diff 哈希不包含当时未跟踪文件；冻结提交后的日志与完整文件清单才是候选对应证据。

本机 Qt 为 MSYS2 UCRT64 Qt 6.11.2，QtQuick 使用匹配的独立 overlay。重新构建时先运行 CMake configure 以更新 `relaxer-source-fingerprint.txt`。开发用例需要 `QML_IMPORT_PATH` 指向匹配的 `share/qt6/qml`，`QT_QPA_PLATFORM=offscreen`、`QT_QUICK_BACKEND=software`、`RELAXER_SKIP_AUDIO_DEVICE_TESTS=1`。命令及完整路径见证据收据。

本轮未运行全量 CTest/QtTest、47 启动矩阵、重复稳定性或 WASAPI。全面测试及最终独立验收交由 Harness；本轮不创建 Tag、不 Push、不发布 Release。
