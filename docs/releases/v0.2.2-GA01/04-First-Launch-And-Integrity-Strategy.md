# GA-01 首次启动、完整性及恢复策略

沿用 RC7：最多 4 个临时工作线程、每文件 64 KiB 读取缓冲、每次启动完整读取并 SHA-256 校验 1,859 个文件；没有元数据缓存、后台常驻、预载、开机启动或联网依赖。实现与运行二进制均未修改。

## 首次使用提示

工程包 README 已告知完整解压、从根 EXE 打开、首次安全扫描可能增加等待、避免重复打开，以及缺失/隔离文件时的恢复步骤。没有加启动动画、常驻服务或伪造准备完成提示。Defender 实时保护本轮保持开启，版本证据在 `evidence/defender-state.json`；没有禁用、排除或调整其策略。未取得能把每段延迟直接归因于 Defender 的跟踪证据。

新解压目录、中文/空格路径、根 EXE 两界面、CMD 退出后根 EXE、默认资料、外部资料、目录移动均通过；每次启动的最终诊断均要求真正首帧、交互探针及正常保存退出，不以 CreateProcess 成功代替完成。

以下是部署验证的少量观察值，**不是新的冷/热启动性能专项**。近似总交互时间由进程总墙钟时间扣除诊断中的交互后区间得到，含退出/等待开销；原始逐阶段 JSON 均保留。没有清空 Windows 缓存或重启，不称为真正冷启动，也不据此宣称“已达 2 秒目标”。

## 安全保证及其边界

未削弱原保护：完整清单、每次实际读取、SHA-256、必要条目、重复/路径穿越/reparse 拒绝、应用与 QML DLL 的源码指纹绑定均保留。8 项真实包负向控制通过：清单缺失、程序篡改、相同长度/mtime 篡改、qwindows 隔离、穿越、重复条目、更新校验和后的错误源码身份、所有者替换 DLL 但未重建清单。均 exit 12，无资料创建、无子进程启动诊断。

当前 PORTABLE 清单为未签名的本地清单，根 EXE 也没有 Authenticode 签名。它能检测相对于既定清单的文件错误，**不提供抵抗同时重写 EXE 和清单的攻击者的独立发行者认证**。这些是原有边界，不是本轮引入的优化或等同签名认证。

主动的 LGPL 修改者可以替换第三方库并更新清单：验证的 Qt6Core.dll PE overlay 先被拒绝，再在明确重建清单后正常显示并交互。该探针不是重建 Qt 的功能/ABI 等价证明。普通启动不会自动信任修改或自动刷新清单。

## 错误和恢复

当前根入口保留原有“缺失/校验/来源不符”的通用错误提示，诊断模式返回原因类别；没有添加具体文件名界面。README 提供安全中心保护历史、完整重新解压与资料备份步骤。模拟隔离通过，不宣称实际触发过防病毒隔离。最终 GA 可做部署文案资源清理，但应另行核验，不在本轮改业务逻辑。
