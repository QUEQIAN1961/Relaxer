# RC1 → RC2 升级与回退

先完全退出旧实例，备份整个 `data`，将副本放入新解压目录并启动。请保留旧备份；本轮开发与验证不使用用户正式数据库。

应用名称、组织名称、数值版本、资料根目录解析和 SQLite schema 保持不变。旧歌曲 ID、路径、歌单、收藏、统计、双语歌词、主题和未知设置键继续使用。升级不清空或重建数据库。

人工分类使用已有 `settings` 表中的独立记录 `lyrics.translationJudgment.v1.<trackId>`，值含 `trackHash` 与 `state`，合法状态为 `needs`、`not-needed`。没有记录、未知状态、无效 ID 或音乐内容哈希不匹配时，均视为待判断。撤销会删除对应设置记录。每次写入成功后才更新界面；删除歌曲时在原有事务内删除对应分类，失败则一起回滚。

分类只表示人的判断，不表示文件已经翻译。完成状态每次按真实歌词及缓存摘要复核推导，不写入 `instrumental`、收藏或歌词正文，不保存混合含义的 translated 布尔值。原歌词外部改动后，可用“刷新判断”或窗口重新激活触发摘要复核。

重复导入同一曲目保留该稳定曲目 ID 的人工判断；新曲目不按列表行号继承判断。路径变化而音乐内容哈希不变不改变所属身份。

回退 RC1 可以读取同一 schema，且会忽略新增设置键，但不会展示或管理新分类。RC1 删除曲目时不认识新分类记录；再次进入 RC2 时内容哈希仍会防止不同歌曲串用旧判断。回退不撤销已成功保存的歌词；如需回到升级前完整状态，应恢复备份。不要同时运行两个版本写同一数据库。
