# 对应源码提供与受控替代重建

本布局用于正式发行准备，但 STATUS.json 明确保留本轮未关闭项；不得将审核材料改名为“完全合规证明”。源包只选择实际组件及已确认静态构建来源，不复制整个 MSYS2 安装、无关二进制包缓存、工具安装、Cargo index/target、部分下载、临时克隆或本轮构建输出。

## 恢复顺序

1. 校验外层 SHA256SUMS 和内部 MATERIALS-SHA256.json。
2. 读取 components 下对应包的原签名源码归档、原 PKGBUILD/SRCINFO/补丁；用 provenance 中绑定关系核对真实二进制来源。签名依据为现有 MSYS2 公钥环的隔离副本，未另建信任根。
3. 源包中某些上游 Git 历史由官方 source package 自带，原 pkgver/build 配方需要这些版本输入，因而按原签名归档保留；它们不是任意开发缓存。额外 verified-vcs-archive-snapshots 给出 6 个精确 Git archive 的代码快照及对应摘要。
4. 在独立构建环境恢复 BUILDINFO 的工具/依赖，不运行宿主系统级包更新。原型源包、工具命令不触碰现有播放器目录或个人 SQLite。
5. 完整应用源码 ZIP 和 bundle 另外交付；其播放器数据/业务保持冻结，仅 OpenCC 源文件头新增法律通知。不能用历史 FFmpeg 7.1 源码替代实际 9.0.2。

## librsvg 替代闭环方案

原始 CI 已印证有效依赖内容，未取得原始锁文件原件。原包身份保持；如需通过受控重建解决静态配置/纳入证据缺口，建立单独的自有构建身份：

- 上游固定为 librsvg 2.63.2；保持已验证原 patch 和功能开关。
- 锁定 rust/Cargo 1.98.1（原 BUILDINFO 版本）、cargo-c 0.10.25、原 Meson 配方和选定 C 依赖，逐项记录实际版本与来源。
- 采用已捕获的 native-registry-replayed 锁 `e5f54deb10851bbecdac99c161478255123bde0474db3bb56ee2ab84c43c852d` 作为**新构建输入**，不称它是原 CI 文件。新增版本源及 registry cksum 一并提供。
- 不再对已捕获锁运行原 prepare 中的 update 步骤；只应用原源码补丁一次，再放入该锁，用 `--locked --offline` 做目标解析/构建。目录型 source replacement 上的旧 pin 曾无效，不能拿其 exit 0 当依赖已经降级的证明。
- target 为 x86_64-pc-windows-gnu；librsvg-c 的 capi/pixbuf 与原 static/shared Meson 参数如原配方保留。GNU patch 第一 hunk 的 fuzz 2 也记录在来源中，不静默改成另一补丁。
- 记录新构建命令、Cargo features、编译/链接输入、来源摘要和 notices；对比 PE 导入与 ABI，测试 librsvg 使用方、图像渲染、插件加载及打包完整性，再独立验收。
- 如采用新 DLL，使用新的自有来源/构建修订，更新相应 manifest、对应源码和验收，不伪称仍是原 MSYS2 2.63.2-1 二进制。此方案没有更改冻结播放器业务或任意 Rust 依赖版本。

本轮已验证该锁下的离线目标 metadata 与完整来源可用性，**没有执行上述 Rust 库重建或替换运行包**。最终门需在采用新组件并验证后，或完成充分的原 CI/配置或保守超集文件级材料后重新裁决。
