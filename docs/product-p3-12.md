# Product P3 candidate, version 0.2.1

Based on `cadfe8756b32483f6319f3ecaf2c312f1ea57634`. These changes need independent Harness acceptance.

- D-R5-04: removed the unused internal `jsonKeys` counter and its benchmark output. No production consumer existed.
- D-R5-05: `Library::saveLyricsChecked` owns both full file guards: before staging and immediately before replacement. Frontends retain the original snapshot, including across modal confirmation. The final guard is mandatory. Private test counters count actual Library reads/digests; reader/parser work outside Library is separate. SQLite and filesystem replacement still do not form a single atomic transaction; an external writer can race the final check and rename.
- D-R5-06: `lyricsFilterStates` batches 256 IDs per query, including track metadata, instrumental status and hash-bound manual judgment. Snapshots live only within synchronous owner-thread operations; async audits take fresh metadata before applying file results. Full content audits and same-size/same-mtime detection remain in place.
- D-R6-02/03: browser line subsets retain their input IDs. Validation uses the exact unique, nonnegative ID set. Cross-thread shutdown is rejected with a warning; arbitrary-thread destruction is unsupported. Normal owners destroy the service and browser backend on their owner thread.
- D-R7-02: explicit featuring/guest credits can match the leading artist when exact title, matching known album, no version markers and duration within one second corroborate it. Full artist matches retain priority. Ambiguous punctuation (including `Artist, Guest`) remains manual because the string alone cannot establish whether it names a band. No global score threshold changes.
- D-R7-03: a song pauses replenishment while its new payload is ranked. A current, credible, unambiguous timed match completes online search and cancels redundant in-flight work. Other songs remain concurrent; weak/plain/failed sources still fall back within existing limits. Requests already dispatched before the match arrived are expected.
- D-R7-04: automatic acceptance counts only successful persistence. Manual/local saves retain separate semantics.
- D-R8-02: `shutdown(false)` leaves the engine usable after a failed save. Both UIs use `PlaybackFacade::requestExit` for retry, exit anyway, and cancel. CLI measurement exits, post-event-loop cleanup and destructors use bounded forced teardown, retaining failure status. Runtime Quit events are routed through the window in interactive runs. Abrupt OS termination is outside this interactive guarantee; no OS shutdown/reboot is performed by tests.
- D-R8-03: queue/current/position/activeSession snapshots are compared with the last successful commit. Failure never marks a snapshot saved. The four-second timer remains unchanged and moving positions still persist. `save()` returns true for a clean no-op. `saved(true)` now means an actual queue snapshot commit; a no-op emits no saved signal, and attempts that fail emit `saved(false)`.
- D-R10-01/02: a failed native close retains the open device state and retries cleanup of only this instance's unique temporary copy. Failed deletion retains ownership for a later close/destructor; permanently locked files may survive process exit with diagnostics. `errorDomain`, `errorStage`, `localError`, and `nativeErrorCode` distinguish local failures from native MCI values. Legacy `errorCode()` passes native DWORDs unchanged; local failures encode `0x80000000 | LocalError` and must be interpreted with the domain. Local values are never passed to `mciGetErrorString`.

Focused suites: `relaxer_lyrics_save_work`, `relaxer_lyrics_persistence`, `relaxer_translation_filter_performance`, `relaxer_translation_coordinator`, `relaxer_lyric_match`, `relaxer_lyrics_search_coordinator`, `relaxer_playback_facade`, `relaxer_qml_c4c5_bridges`, and `relaxer_midi`. Test data is synthetic; HTTP/MCI faults are injected locally. No live paid request is required.
